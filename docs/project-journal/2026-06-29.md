# Witness World Pipeline

The Witness World now consists of:

* Visual Extraction
* Character Bible
* Environment Bible
* Composition Bible
* Object Bible
* Scene Bible

These components are generated automatically from the Blueprint.

The user no longer needs to run each step manually.

# UI Direction

The interface should present the witness experience rather than the internal AI architecture.

Instead of exposing:

* Visual Extraction
* Character Bible
* Environment Bible
* Composition Bible
* Object Bible
* Scene Bible

the interface should simply communicate:

Build Witness World

with visible progress.

Developer Mode will expose the internal Bibles when needed.

---

# Important Discovery

Testing revealed three major fidelity problems.

## 1. Character Drift

The same witness or grandmother is redesigned between images.

Future solution:

Identity Lock

---

## 2. Room Drift

The Japanese room changes between scenes.

Future solution:

Room Lock

---

## 3. Impossible Condition Drift

The witness emerges from the tatami.

The model incorrectly creates a visible hole.

The testimony never described a hole.

Future solution:

Impossible Condition Lock

The appearance must be preserved without introducing explanations.

---

# Design Shift

A major realization today:

The challenge is no longer extracting information.

The challenge is preserving information.

Future work should prioritize Lock layers over creating additional Bible types.

Examples:

* Identity Lock
* Room Lock
* Impossible Condition Lock
