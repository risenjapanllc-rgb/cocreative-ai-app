# Witness World AI Review Checklist

## Purpose

This checklist must be completed before approving any AI-generated code.

Every item should be answerable with YES or NO.

If any required item is NO,
the change should not be merged until resolved.

---

# 1. Mission

□ Does this change preserve the mission of Witness World?

□ Does it preserve testimony instead of optimizing images?

□ Does it avoid changing project philosophy?

---

# 2. Architecture

□ Does the change respect the pipeline architecture?

□ Does every stage keep its own responsibility?

□ Has no responsibility moved to another stage?

□ Does truth still flow only forward?

---

# 3. Witness Fidelity

□ Were witness facts preserved?

□ Were impossible conditions preserved?

□ Were no new facts invented?

□ Were no witness facts removed?

---

# 4. Scene Bible

□ Was Scene Bible left immutable?

□ Were no witnessed facts rewritten?

---

# 5. Timeline

□ Does Timeline still represent only the current moment?

□ Were future events avoided?

□ Were multiple scenes not merged?

---

# 6. Director

□ Does Director remain an observer?

□ Did Director avoid creating events?

□ Did Director avoid inventing poses or actions?

---

# 7. Render Contract

□ Does Render Contract preserve world facts?

□ Were no facts simplified for image convenience?

---

# 8. Prompt Translator

□ Does the Prompt only translate?

□ Was no new story introduced?

□ Was no symbolism added?

---

# 9. Generalization

□ Is the solution general?

□ Is there no dream-specific hardcoding?

□ Can this work for future testimonies?

---

# 10. Evidence

□ Was the cause confirmed before code was changed?

□ Were logs reviewed?

□ Was the relevant code inspected?

□ Was the conclusion supported by evidence?

---

# 11. Scope

□ Was only the intended file changed?

□ Were unrelated files left untouched?

□ Is the modification minimal?

---

# 12. User Corrections

□ Were user corrections preserved?

□ Did the AI avoid overriding user statements?

---

# 13. Code Quality

□ Is the code easier to understand?

□ Is the responsibility clearer?

□ Were unnecessary abstractions avoided?

---

# 14. Testing

□ Is there a clear verification method?

□ Can success be observed?

□ Can failure be reproduced?

---

# 15. AI Behavior

□ Did the AI avoid guessing?

□ Did the AI ask questions when uncertain?

□ Did the AI explain the purpose of the change?

□ Did the AI avoid unsupported promises?

---

# Final Decision

Merge only if:

Mission preserved:
□ YES

Architecture preserved:
□ YES

Witness preserved:
□ YES

Evidence confirmed:
□ YES

General solution:
□ YES

If any answer is NO,
request revision before merging.
